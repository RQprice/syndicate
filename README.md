# SYNDICATE

Настольное приложение для розыгрыша игровой добычи между участниками гильдии.
Позволяет вести список игроков, учитывать БМ при выборе победителей, импортировать
участников со скриншотов, сохранять анимацию в MP4 и просматривать историю результатов.

Приложение ориентировано на Windows. Интерфейс построен на Tkinter, графика —
на Pillow и OpenCV. OCR выполняется локально через Tesseract и RapidOCR;
изображения не отправляются в облачный сервис распознавания.

## Возможности

- добавление, переименование и удаление участников, редактирование БМ;
- список в две колонки с автоматической сортировкой по убыванию БМ и давностью побед;
- выбор участников галочками, команды «Выбрать всех» и «Убрать выделение»;
- настройка влияния БМ от 0 до 100% и отображение вероятностей на колесе;
- накопительный импорт скриншотов с проверкой и исправлением результатов;
- распознавание ников на латинице, кириллице, с китайскими и японскими символами;
- запоминание пользовательских исправлений ников;
- изображение награды из буфера и настройка количества её экземпляров;
- последовательный выбор победителей без повторного выбора той же записи в серии;
- плавное вращение с целевой частотой до 60 FPS и исчезновение выигравших секторов;
- экспорт результата в MP4 и журнал сохранённых розыгрышей;
- поиск истории по игроку и награде, календарный фильтр по датам;
- автоматическое сохранение списка, влияния БМ и замен ников;
- масштабирование интерфейса под монитор и прокрутка при переполнении списка.

## Запуск

Для готовой сборки запустите `SYNDICATE.exe`. Python и отдельная установка
OCR-компонентов для сборки, созданной через `build.ps1`, не требуются.

Для запуска исходников используйте Python с Tkinter; текущий проект проверен
на Python 3.11. Из корня проекта выполните:

```powershell
py -m pip install -r requirements.txt
py app.py
```

После установки зависимостей также можно запускать `launch.bat`: он открывает
приложение через `pythonw` без консоли. Команда `pythonw` должна быть доступна в PATH
и относиться к окружению с установленными зависимостями.

Для OCR нужны дополнительные ресурсы, которые не устанавливаются командой pip:

- `vendor/Tesseract-OCR/` — `tesseract.exe` и языковые данные `eng`/`rus`
  в `tessdata_best` либо `tessdata`;
- `vendor/RapidOCR-models/` — ONNX-модели распознавания английского,
  кириллического и китайского текста, а также модель обнаружения текста.

В текущем проекте эти ресурсы находятся в `vendor`. Сохраняйте комплект моделей
при переносе исходников. Tesseract также может быть найден через PATH, если
рядом с его исполняемым файлом есть `tessdata`.

## Участники

Кнопка «+ Добавить» создаёт строку для ручного ввода ника и БМ с включённой
галочкой. Поля редактируются прямо в списке. Удаление крестиком убирает игрока
из списка, а снятие галочки исключает его только из текущего розыгрыша.

Имена, БМ и влияние сохраняются автоматически после изменения. Список сортируется
по убыванию БМ; при вводе БМ перестановка строки откладывается до завершения
редактирования. Поддерживаются пробелы между разрядами и точка или запятая
как десятичный разделитель. БМ должен быть конечным неотрицательным числом,
влияние — числом от 0 до 100. Некорректные числовые поля выделяются и не сохраняются.
Имена сохраняются длиной до 40 символов; пустые имена не включаются в данные.

Галочки действуют только в текущем сеансе: при каждом запуске все загруженные
участники выключены. Жёсткого ограничения в 50 игроков нет — прокрутка появляется,
когда строки перестают помещаться в доступную область.

В текстовых полях работают `Ctrl+C`, `Ctrl+V`, `Ctrl+X` и `Ctrl+A`, в том числе
при русской раскладке клавиатуры.

## Импорт из буфера обмена

1. Нажмите «Из буфера» в панели участников.
2. Скопируйте скриншот списка гильдии и нажмите `Ctrl+V` или «Вставить скриншот».
3. Добавьте остальные изображения. Ненужную миниатюру можно удалить щелчком.
4. Нажмите «Распознать» и дождитесь обработки набора скриншотов.
5. Проверьте объединённый список: исправьте ники и БМ, удалите ненужные строки.
6. Нажмите «Добавить», чтобы применить импорт.

Новые игроки отмечаются значком `NEW`, изменившийся БМ — `UPD`. Имена с низкой
уверенностью распознавания выделяются рамкой. Новые участники добавляются без
галочки; существующим по совпавшему имени без учёта регистра обновляется БМ,
а их выделение сохраняется. Отсутствующие на скриншотах игроки не удаляются.

Повторяющиеся результаты объединяются по нормализованному нику либо по сочетанию
одинакового БМ и похожего имени. Это эвристика: результат нужно проверять.
Кнопка «К скриншотам» позволяет вернуться к изображениям и повторить распознавание,
но ручные правки предыдущего результата не сохраняются как отдельный черновик.

В Windows при возвращении в окно импорта приложение может автоматически добавить
новое изображение, если содержимое буфера изменилось. Оно читает текущее содержимое,
а не всю историю буфера. Вставка в текстовое поле продолжает работать как ввод текста.

OCR ищет контуры игровых карточек ожидаемых пропорций, приводит каждую к размеру
350 × 105 и распознаёт фиксированные области имени и БМ внутри карточки.
Поэтому положение карточек на скриншоте может меняться, но произвольная вёрстка
и другие виды таблиц не поддерживаются автоматически. Для распознаваемого БМ
принимается диапазон 10 000–999 999 999; карточки без имени или допустимого БМ
пропускаются. При подтверждении импорта БМ должен быть целым неотрицательным числом.

### Замены ников

Исправление ника в результатах запоминается при подтверждении импорта.
В следующий раз соответствующее ошибочное написание автоматически заменяется
правильным. Сопоставление учитывает нормализацию регистра и пробелов.

Кнопка `⇆` в окне импорта открывает «Замены ников», где можно просматривать
и удалять сохранённые соответствия. Новые правила и их обновления создаются
через исправление результатов импорта. Это словарь замен, а не переобучение модели.

## Как БМ влияет на шанс

Минимальный и максимальный БМ определяются по всему списку гильдии, включая
участников без галочки. В самом раунде участвуют только выбранные игроки,
которые ещё не победили в текущей серии:

```text
influence = influence_percent / 100
normalized_bm = (bm - min_bm) / (max_bm - min_bm)
bm_share = normalized_bm / sum(current_round_normalized_bm)
probability = (1 - influence) / participant_count + influence * bm_share
```

При влиянии `30%` оставшиеся `70%` делятся поровну, а `30%` распределяются
пропорционально нормализованным БМ. Это не прямая пропорция исходным значениям БМ.

- При `0%` шансы равны.
- При `100%` равная составляющая отсутствует, и участник с минимальным БМ
  может иметь нулевой шанс.
- Если БМ всей гильдии одинаков или сумма нормализованных значений текущего
  раунда равна нулю, используются равные вероятности.

Например, если весь список состоит из трёх выбранных игроков с БМ 100, 200 и 300,
при влиянии 50% их шансы составят 16,67%, 33,33% и 50%.

Победитель выбирается перед анимацией взвешенным случайным выбором через `secrets`.
Колесо останавливается внутри его сектора. Размеры секторов соответствуют
вероятностям; подписи округляются до двух знаков. Длинные ники сокращаются
только для отображения на колесе, у очень маленьких секторов подпись может отсутствовать.

## Награда и розыгрыш

1. Выберите минимум двух участников и задайте влияние БМ.
2. При необходимости скопируйте изображение награды и нажмите пустую карточку
   над колесом, чтобы вставить его.
3. Укажите количество экземпляров награды кнопками «−»/«+» или вручную.
4. Нажмите «КРУТИТЬ КОЛЕСО» и дождитесь завершения серии.
5. Сохраните результат в MP4 либо нажмите «ОТМЕНА» для возврата к исходному колесу.

Одна серия разыгрывает один тип награды. Поле количества принимает значения
от 1 до 9999, но наград не может быть больше, чем выбранных участников.
Нажатие на заполненную карточку удаляет изображение и сбрасывает количество до одного.

При нескольких наградах после каждого раунда выигравший сектор подсвечивается,
плавно исчезает, а шансы оставшихся игроков пересчитываются. Победившая запись
не участвует в следующих раундах этой серии. Основной список и галочки сохраняются;
в отдельном следующем розыгрыше эти игроки могут победить снова.

Одиночное вращение длится около 4,8 секунды, в серии — около 3,6 секунды на раунд,
плюс паузы и переходы. На время вращения редактирование участников, награды
и количества блокируется. В конце показываются все победители серии.
Значок `⇅` в правом верхнем углу карточки сортирует эту надпись по убыванию БМ.
Порядок побед в MP4 и журнале при этом не изменяется.

Название награды распознаётся локально после завершения серии. Без изображения
в журнал записывается «Награда не указана», при неудачном OCR — «Награда не распознана».
Ручного поля для исправления названия награды перед сохранением нет.

## MP4 и подтверждение результата

После розыгрыша в фоне готовится видео. Кнопка «СОХРАНИТЬ РЕЗУЛЬТАТ» становится
доступной, когда завершены подготовка MP4 и распознавание награды. Пользователь
выбирает путь в стандартном диалоге сохранения.

Видео имеет размер **820 × 912**, частоту **24 FPS** и не содержит звука.
В него входят название приложения, счётчик участников, карточка награды,
количество при значении больше одного, анимация колеса и финальный результат.
Правая панель участников в видео не включается. Сцена отрисовывается из состояний
розыгрыша, а не записывается с рабочего стола. В конце результат показывается
около двух секунд.

Для кодирования сначала используется доступный H.264 через Windows Media Foundation,
при его недоступности — MPEG-4 через FFmpeg backend OpenCV. Конкретный кодек
зависит от окружения. Для восточноазиатских символов в видео используются
подходящие установленные шрифты Windows.

**История пополняется только после успешной записи MP4.** Отмена выбора файла
не подтверждает результат. Повторное сохранение текущего результата не создаёт
дубликатов в истории. Если видео записано, а журнал сохранить не удалось,
приложение сообщает об ошибке; MP4 остаётся на диске. При ошибке подготовки MP4
кнопка сохранения недоступна — отдельного подтверждения только в журнал нет.

«ОТМЕНА» сбрасывает текущий результат и восстанавливает исходное колесо.
Если результат уже сохранён, эта кнопка позволяет перейти к следующему розыгрышу,
но не удаляет видео или историю. Изменение участников, галочек или влияния БМ
после розыгрыша также сбрасывает результат, включая ещё не сохранённое видео.

## История

Кнопка «История» открывает таблицу победителей, наград и времени. Последние
добавленные записи отображаются первыми. Каждый победитель серии сохраняется
отдельной строкой с общей наградой и временем завершения серии.

В основном списке колонка «Последняя победа» показывает номер последнего розыгрыша
игрока относительно текущего конца истории.
Победители одной серии имеют одинаковый номер розыгрыша. Если записей для игрока
нет, отображается «Никогда». Регистр имени учитывается: например, `XmelON` и
`Xmelon` считаются разными персонажами.

- Поиск работает сразу при вводе, без учёта регистра, по имени и награде.
  Все введённые слова должны присутствовать в совокупном тексте этих полей.
- Календарь позволяет выбрать один день или диапазон включительно, переключать
  месяцы и сбрасывать период. Поиск и фильтр дат применяются совместно.
- Счётчик показывает общее число записей либо число найденных из общего количества.
- Текст полей можно выделять и копировать; редактирование записей не предусмотрено.
- Крестик удаляет запись после подтверждения из таблицы и JSON-журнала.
  Сохранённое видео при этом не удаляется.

Время отображается как `ДД.ММ.ГГГГ ЧЧ:ММ`, в файле сохраняется ISO-метка
с секундами и часовым поясом. История не содержит путь к MP4, снимок состава
участников, их вероятности или настройки розыгрыша.

## Данные

| Файл / состояние | Что хранится |
| --- | --- |
| `data.json` | Имена и БМ участников, `bm_influence_percent`, `nickname_corrections` |
| `draw_log.json` | Версия формата и записи с `winner`, `reward`, `timestamp` |
| MP4 по выбранному пути | Видео сохранённого результата |
| Только память приложения | Галочки, изображение и количество награды, скриншоты импорта, неподтверждённый результат |

JSON-файлы находятся рядом с `app.py` при запуске исходников или рядом
с `SYNDICATE.exe` при запуске сборки. Поэтому исходники и EXE в `dist`
используют отдельные данные. При отсутствии `data.json` создаётся пустой список
со стандартным влиянием БМ **100%**. Отсутствующий журнал означает пустую историю.

Данные записываются через временный `.tmp` с последующей заменой основного файла.
Автоматических резервных копий, синхронизации и восстановления незавершённой
сессии нет. Для переноса списка и истории скопируйте оба JSON-файла;
видеозаписи переносятся отдельно.

Участники не имеют постоянных идентификаторов, ручные дубли ников не запрещены.
Неповторяемость победителей внутри серии относится к записям списка:
две строки с одинаковым ником считаются разными участниками.

## Сборка в один EXE

Из корня проекта с установленными зависимостями выполните:

```powershell
py -m pip install pyinstaller
.\build.ps1
```

Для сборки нужны OCR-компоненты в `vendor`, иконки в `imgs` и начальный `data.json`.
Скрипт включает OCR-ресурсы и иконки в оконный EXE и создаёт:

- `dist/SYNDICATE.exe`;
- `dist/data.json`, если файла ещё нет; существующие данные сохраняются;
- `dist/SYNDICATE.zip` с EXE и `data.json`.

История `draw_log.json` в архив автоматически не включается. Чтобы собрать
только EXE с данными без создания ZIP, используйте:

```powershell
.\build.ps1 -SkipZip
```

Скрипт `build.ps1` вычисляет пути к ресурсам относительно своей папки.
Существующий `SYNDICATE.spec` содержит абсолютные пути компьютера, где он был
создан; для сборки в другом расположении используйте скрипт.

## Структура проекта и проверки

| Путь | Назначение |
| --- | --- |
| `app.py` | Точка запуска и совместимый фасад публичных импортов |
| `syndicate/` | Модули главного окна, участников, истории, импорта, вероятностей, хранилищ, MP4 и общих UI-компонентов |
| `ocr_import.py` | Получение изображения из буфера и распознавание игроков/наград |
| `tests/` | Проверки логики, окон, OCR и видео |
| `ocr_samples/` | Эталонные изображения и ожидаемые результаты OCR |
| `imgs/` | Иконки и изображения гайда |
| `vendor/` | Локальные OCR-компоненты и модели |
| `build.ps1` | Сборка EXE и переносимого архива |

Запуск существующих тестов из корня проекта:

```powershell
py -m unittest discover -s tests -v
```

Тесты используют Tkinter, локальные OCR-модели и видеокодеки; для проверок окон
нужна графическая сессия. Набор проверяет вероятности, хранилища, замены ников,
несколько победителей, отмену, историю с поиском и датами, количество наград,
сочетания клавиш, масштабирование, шрифты, OCR на образцах и кодирование MP4.

Актуальная карта модулей и подсказки по выбору файлов для изменений:
[архитектура проекта](docs/architecture.md). Более подробное описание поведения:
[обзор реализации](docs/APP_OVERVIEW_RU.md). Изображения в `imgs/Гайд` относятся
к более раннему состоянию интерфейса и могут не показывать все текущие элементы.
