1. Назначение продукта

SYNDICATE — настольное приложение для офицеров и лидера игровой гильдии, предназначенное для проведения розыгрышей и распределения лута между участниками.

Основная задача приложения — обеспечить максимально честное, прозрачное и независимое распределение игрового лута с использованием формализованной механики определения вероятностей и случайного выбора победителя.

2. Целевая аудитория

Основные пользователи:

лидер гильдии;
офицеры гильдии, отвечающие за распределение лута;
потенциально несколько пользователей внутри одной гильдии.

На текущем этапе приложение проектируется для использования в рамках одной гильдии.

3. Основной пользовательский сценарий

Типичный сценарий использования приложения:

Пользователь запускает приложение.
Обновляет актуальные значения БМ игроков вручную либо через импорт.
Выбирает игроков, принимающих участие в конкретном розыгрыше.
Указывает параметры розыгрыша.
Запускает колесо.
Приложение определяет победителя или победителей.
Пользователь получает визуальный результат розыгрыша.
Результат сохраняется в истории.
При необходимости пользователь экспортирует результат в виде видео.

Основная механика розыгрыша является стабильной частью продукта и в дальнейшем существенно изменяться не планируется.

4. Данные

Основными пользовательскими данными являются:

список игроков;
БМ игроков;
настройки розыгрыша;
история проведённых розыгрышей;
результаты розыгрышей;
вспомогательные данные приложения.

Наиболее ценными данными являются история розыгрышей и сохранённые результаты.

Потеря этих данных нежелательна, однако на текущем этапе не считается критической для работы пользователя или гильдии.

5. Основные инженерные приоритеты

Разработка должна сохранять баланс между:

простотой использования;
производительностью;
объёмом функциональности;
сопровождаемостью;
расширяемостью программного решения.

Расширяемость является существенным требованием, поскольку предполагается дальнейшее постепенное добавление вспомогательных функций без изменения основной механики розыгрыша.

6. Масштаб использования

На текущем;

не является публичным массовым продуктом.

Архитектура не обязана заранее обеспечивать масштабирование до большого количества пользователей, однако по возможности не должна создавать необоснованных препятствий для дальнейшего развития.

7. Распространение

Публичное распространение приложения в настоящее время не планируется.

В дальнейшем развитие проекта может привести к публичному распространению, поэтому желательно не принимать архитектурные решения, которые полностью привязывают приложение к одному конкретному компьютеру или одному конкретному пользователю без необходимости.

8. Стратегия развития

Проект рассматривается как развивающееся приложение.

Основная механика проведения розыгрышей считается сформированной и должна оставаться стабильной.

Дальнейшее развитие предполагается преимущественно за счёт добавления вспомогательной функциональности вокруг существующего процесса:

дополнительной информации об игроках;
статистики;
истории;
аналитики;
синхронизации данных;
улучшения удобства работы.
9. Возможные будущие функции
9.1. Информация о последней победе игрока

В основном списке игроков может отображаться информация о том, как давно участник последний раз выигрывал в розыгрыше.

Цель функции — предоставить офицеру дополнительную информацию при принятии решения о включении игрока в следующий розыгрыш.

Эта информация не должна автоматически изменять вероятность победы без отдельного изменения требований к основной механике.

9.2. Статистика игроков

Отдельное окно статистики может содержать:

количество побед игрока;
историю побед;
историю изменения БМ;
график изменения БМ;
активность игрока;
участие в различных мероприятиях;
дополнительные агрегированные показатели.
9.3. Синхронизация данных

В перспективе может появиться синхронизация данных между несколькими пользователями приложения.

Цель — позволить нескольким офицерам одной гильдии работать с общей актуальной информацией.

Механизм синхронизации на текущем этапе не определён.

10. Текущее состояние продукта

Текущая реализация приложения удовлетворяет основным потребностям пользователей.

Задачей дальнейшей разработки является не переписывание работающей системы, а контролируемое развитие существующего решения при улучшении его внутренней архитектуры, тестируемости, сопровождаемости и готовности к добавлению новых функций. этапе приложение:

рассчитано на одну гильдию;
может использоваться несколькими людьми;
не требует поддержки большого количества независимых организаций или гильдий
