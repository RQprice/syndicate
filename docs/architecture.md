# Архитектура SYNDICATE

## Общая схема

`app.py` остаётся стабильной точкой запуска и слоем совместимости. Рабочий код
находится в пакете `syndicate`, а OCR вынесен в отдельный специализированный
модуль `ocr_import.py`.

Зависимости направлены от общих модулей к интерфейсу:

```text
theme / models / platform
          ↓
probabilities / storage / video / widgets / wheel_rendering
          ↓
history_ui / import_ui
          ↓
participants_ui
          ↓
draw_workflow / application
          ↓
app.py
```

`ocr_import.py` используется экраном импорта и главным окном, но не зависит от
UI приложения.

## Карта модулей

| Файл | Ответственность | Когда изменять |
| --- | --- | --- |
| `app.py` | Точка запуска и обратная совместимость старых импортов | Только при изменении запуска или публичных импортов; новую логику сюда не добавлять |
| `syndicate/application.py` | Корневое окно, адаптивная компоновка и соединение подсистем приложения | Изменения общей компоновки, запуска окна и состояния верхнего уровня |
| `syndicate/draw_workflow.py` | Сценарий одиночного/множественного розыгрыша, выбор победителей, переходы между раундами, подготовка результата, OCR награды и координация MP4 | Изменения последовательности розыгрыша и действий после остановки колеса |
| `syndicate/wheel_rendering.py` | Сглаженная отрисовка колеса, секторов, эмблемы и кадров сцены результата | Изменения внешнего вида колеса или записываемой сцены |
| `syndicate/participants_ui.py` | Двухколоночный список участников, редактирование, выбор, сортировка, последние победы и панель действий | Изменения строк участников и элементов управления правой панели |
| `syndicate/mass_distribution_ui.py` | Независимая левая рабочая область массового распределения, показываемая вместо колеса | Развитие сценария массового распределения без связи с колесом |
| `syndicate/mass_distribution.py` | Чистые модели событий, распределение целых наград, накопление долей и восстановление отдельной очереди | Правила справедливости и формат отчётов массового режима |
| `syndicate/mass_distribution_dialogs.py` | Настройки предметов с вкладками «Делимые» и «Предметы для розыгрыша», просмотр сохранённых отчётов | Интерфейс настроек и отчётов массового режима |
| `syndicate/import_ui.py` | Окно импорта скриншотов, экран проверки OCR и редактор замен ников | Изменения пользовательского сценария импорта и внутренних замен ников |
| `syndicate/history_ui.py` | Окно истории, поиск, фильтр дат, удаление записей и календарь | Изменения таблицы истории и фильтрации |
| `syndicate/penalty_ui.py` | Окно настройки штрафа победителей и шкалы восстановления шанса по участиям | Изменения интерфейса настройки штрафов |
| `syndicate/widgets.py` | Переиспользуемые стилизованные элементы: кнопки, чекбоксы, удаление, карточка награды, количество, анимированное многоточие | Общие визуальные элементы и их поведение |
| `syndicate/probabilities.py` | Формула весов/вероятностей по БМ и безопасный случайный выбор | Любые изменения математической модели розыгрыша |
| `syndicate/penalties.py` | Восстановление текущего этапа штрафа из истории побед и участий | Расчёт коэффициента и оставшихся участий |
| `syndicate/models.py` | Модели данных и чистые преобразования: участник, результат, замена ника, форматирование БМ, статистика последней победы | Поля предметной области и независимые от UI вычисления |
| `syndicate/storage.py` | Чтение и запись `data.json` и `draw_log.json` | Форматы хранения, миграции и файловые операции |
| `syndicate/video.py` | Низкоуровневое кодирование готовых кадров в MP4 | Кодек, FPS, параметры и ошибки кодирования |
| `syndicate/platform.py` | Пути приложения, масштабирование, Windows title bar/DPI/icon, буфер обмена и сочетания клавиш полей | Платформенные особенности Windows и Tk |
| `syndicate/theme.py` | Палитра, размеры дизайн-макета и общие константы | Глобальная тема и базовые параметры масштаба |
| `ocr_import.py` | Распознавание участников и русскоязычных названий наград, работа с локальными OCR-движками | Алгоритмы OCR и выбор OCR-моделей |

## Данные и ресурсы

- `data.json` — участники, влияние БМ, настройки штрафов, таблица пользовательских замен ников и независимые списки `mass_distribution.divisible_items` / `mass_distribution.raffle_items`.
- `draw_log.json` — история розыгрышей.
- `mass_distribution_log.json` — отдельная история массового распределения версии 1 и точный снимок балансов `balance_cache`; выдачи остаются источником для восстановления.
- `imgs/` — иконки и изображения интерфейса.
- `vendor/` — локальные OCR-компоненты, модели и видеокодеки.
- `ocr_samples/` — эталонные изображения и ожидаемые результаты OCR-тестов.

`draw_log.json` использует формат версии 3: каждый результат дополнительно
хранит неизменяемый снимок участников розыгрыша и флаг применения штрафа.
При запуске журналы версий 1–2 атомарно переписываются в версию 3; старые
записи получают пустой список участников и `penalty_applied: false`, а
неизвестные поля сохраняются.
В режиме исходников файлы данных находятся рядом с приложением; в собранной
версии — рядом с EXE.

Массовый режим не читает историю розыгрышей для расчёта наград. Его алгоритм
`fair-share-v4` считает каждую выбранную стопку вида предмета одной долей;
право на неё делится поровну между присутствующими. Накопленный баланс ведётся
по нормализованному названию события и нику, а дополнительный баланс — по виду
предмета. Больший общий баланс имеет приоритет, затем учитывается баланс по
предмету, затем случайный выбор. Расчёты используют точные `Fraction`.
Для делимой стопки перебираются размеры групп от одного до числа доступных
участников (не больше количества единиц). Основная порция для варианта равна
`ceil(количество / размер группы)`, последний получатель получает положительный
остаток не больше основной порции; фактическое число получателей может быть
меньше перебираемого размера. Одинаковые варианты порций рассматриваются один раз.
Выбирается минимальная сумма квадратов общих балансов после гипотетической выдачи,
при равенстве — сумма квадратов предметных балансов, затем случайный вариант.
Поскольку суммарный баланс одинаков для всех вариантов, это минимизация разброса
балансов. Префиксные суммы позволяют сравнивать варианты за O(число участников),
не копируя весь баланс для каждой группы. Точные `Fraction` исключают округление.
Получатели выбираются сортировкой общего и предметного баланса после случайного
перемешивания для разрешения равенств; более высокий приоритет получает большую
порцию. В отчёте основные порции перемешаны, меньший остаток идёт последним.
Работа ограничена числом участников, а не размером стопки. Делимые предметы
списывают `выданное количество / количество стопки` доли;
неделимые передаются целиком и списывают одну долю. Даты не входят в ключ
очереди, но нормализованная дата и название события образуют ключ защиты
от повторной выдачи. Пакет проверяется целиком и записывается атомарной
заменой файла до открытия отчёта. В журнале сохранены снимки участников,
настроек, выдач, балансов и seed для воспроизведения случайного выбора.
Пересчёт поддерживает старые отчёты `fair-share-v1` с произвольными порциями
и `fair-share-v2` с равными порциями по наибольшему делителю, не меняя выдач.
Для `fair-share-v3` сохраняется проверка порций при максимальном составе,
для `fair-share-v4` — структуры основных порций и остатка в выбранной группе.
`balance_cache` содержит версию снимка, алгоритм `fair-share-v1`, нормализованные
балансы по событиям/предметам/никам и SHA-256 канонического JSON истории и снимка.
Версия правил учёта долей в снимке не меняется: новый способ выбора порций
не меняет начисление и списание долей, старые снимки остаются совместимыми.
Значения дробей хранятся как строки (`1/3`, `-2/3`, `0`). Загрузка проверяет
контрольные суммы и структуру снимка, нулевую сумму долей и согласованность общего
и предметных балансов; при успехе полного пересчёта выдач нет. При отсутствии,
устаревании или повреждении снимка выполняется `distribution_balances` — полный
пересчёт с проверкой истории. Повреждённая история по-прежнему блокирует выдачу.
`prepare_distribution` получает проверенный баланс от хранилища, копирует его,
применяет только новые выдачи и строит обновлённый снимок. Снимок и отчёт записываются
одной атомарной заменой файла; состояние в памяти подтверждается после успешной
записи. Старые журналы получают снимок при следующем распределении, чтение само
по себе не переписывает пользовательский файл. Проверка хешей и запись JSON
по-прежнему проходят по истории, но не повторяют расчёты дробных долей.
У новых записей событий и предметов поле `source_position` сохраняет порядок импорта.
Представление отчёта сортирует события и предметы по этому полю, не меняя порядок их
расчёта в журнале и восстановление очереди. Для старых записей без этого поля
используется сохранённый порядок.

## Как выбирать файлы для задачи

- Сначала определить зону изменения по таблице выше и открыть только этот
  модуль, его прямые зависимости и соответствующие тесты.
- Для новой формулы вероятности обычно достаточно
  `probabilities.py`, `models.py` и `tests/test_probabilities.py`.
- Для строки участника — `participants_ui.py`, а для вычисления последней
  победы дополнительно `models.py` и `storage.py`.
- Для OCR награды — `ocr_import.py`; `import_ui.py` относится прежде всего к
  распознаванию списка участников, а `application.py` запускает OCR награды.
- Для параметров MP4 — `video.py`; внешний вид записываемой сцены находится в
  `wheel_rendering.py`, а порядок кадров — в `draw_workflow.py`.
- Для истории — `history_ui.py`, `storage.py`, `models.py` и тесты истории.

Чтение всего репозитория требуется только для действительно сквозных изменений.

## Проверки

В UI массового режима запросы перерисовки скрытого колеса откладываются до
возврата к розыгрышу. Обновления области прокрутки объединяются через один
`after_idle`, а неизменившиеся размеры не вызывают повторную настройку окон.
Окно отчётов сначала показывает карточки распределений по две в ряд, новые сверху;
в названии короткая дата, ниже полная дата, число уникальных участников, позиций наград и событий.
Выбор открывает конкретный отчёт в том же окне; после распределения этот
этап выбора пропускается. Поиск и копирование отчёта удалены. При открытии
конкретного отчёта все события свёрнуты, создаются только заголовки.
Раскрытое событие имеет акцентный контур. Детали строятся при раскрытии
одного события и удаляются при его закрытии. Перемещение окна
без изменения размеров не запускает пересчёт переноса строк или прокрутки.
Подсветка обновляется только при смене строки. `primary_action_button` задаёт
общий стиль для кнопок «Крутить колесо» и «Распределить».
`CopyNickname` рисует компактную скруглённую область имени в Canvas и копирует
точный ник по клику (также Enter/Space при фокусе). Фиксированное место справа
зарезервировано под «Скопировано»: появление и затухание не меняют размеры строки.
При наведении на ник подсветка строки выключается; выход в остальную область
строки возвращает её. Подтверждение копирования использует тот же ACCENT,
Segoe UI Semibold 8 и немедленное затухание за 18 шагов по 65 мс, что список участников.
В режиме колеса `WinnerNicknameCopy` добавляет копирование отдельных ников
к существующему `result_label`, не заменяя его и не меняя геометрию. Невидимый,
неуправляемый Canvas использует ту же нативную раскладку текста Tk для определения
ника под курсором, включая переносы и Unicode. Разделители и пустые области
некликабельны, фон текста при наведении не меняется. Подтверждение размещается
в отдельной безрамочной накладке поверх текста левым нижним углом к точке клика,
с небольшой подложкой в пределах карточки, и не влияет на компоновку.
Текст и подложка затухают вместе через `-alpha` за 18 шагов по 55 мс;
повторный клик передаётся нику под уведомлением. Сортировка,
очистка результата и перестроение UI сбрасывают карту текста и отменяют таймер.
Анимация запускается только после успешного копирования, повторный клик
перезапускает её; таймер отменяется при уничтожении виджета или закрытии события.
Обработчики глобальных кликов учитывают, что `event.widget` для нативных окон
ttk может быть строковым путём, и не вызывают методы виджета у этой строки.

Полный набор тестов запускается из корня:

```powershell
py -m unittest discover -s tests -v
```

Быстрая проверка синтаксиса и импортов:

```powershell
py -m compileall -q app.py ocr_import.py syndicate
```

Точка запуска приложения не изменилась:

```powershell
py app.py
```

Сборка по-прежнему выполняется `build.ps1`; архитектурное разделение не требует
изменений пользовательских данных или команды запуска.
